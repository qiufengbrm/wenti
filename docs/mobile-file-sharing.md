# 手机版文件发送覆盖清单

本功能仅在项目现有 `sm` 断点以下显示「发送文件」，桌面端与原下载、预览行为保持不变。

## 统一实现

- `useFileShare`：通过现有鉴权接口获取文件，读取服务端文件名与 MIME，构造 `File`，调用 `navigator.canShare` 和 `navigator.share`。
- `MobileFileShareButton`：统一加载、二次点击、取消、错误和下载回退状态。
- 单个资料文件的分享请求使用同源 `?share=1` 文件流；普通下载仍使用原有 OSS 签名下载方式。
- 分享内存上限为 100MB。单文件读取 `Content-Length`，ZIP 读取服务端 `X-File-Source-Size`，超限时不载入 Blob，直接回退原下载。

## 特殊回退

- 浏览器不提供文件 Web Share、目标文件类型不被 `canShare` 接受：下载已获取的原文件。
- 文件超过 100MB：不读取文件体，使用原下载流程。
- 历史遗留外部链接因 CORS 无法被浏览器读取：保留页面原下载入口，并显示错误提示，不跳转到裸接口响应。
- 权限不足或接口返回错误：显示错误，不尝试绕过鉴权。
- 用户取消系统分享：保留已准备文件，可再次点击。
- 异步准备后用户激活失效：显示「再次点击发送」，第二次点击只调用系统分享，不重复下载。

## 真机验收步骤

对下表每个浏览器，分别用普通志愿者和管理员账号执行：

1. 打开资料中心，选择一个小于 100MB 的 PDF、图片、Office 文件和其他二进制文件，点击「发送文件」。
2. 确认加载期间按钮不可重复点击；若出现「再次点击发送」，再次点击后应打开系统分享面板。
3. 在系统分享面板中分别选择微信、QQ及“存储到文件”（以系统实际提供的接收应用为准），确认文件名、扩展名和内容正确。
4. 测试文件夹 ZIP 和批量 ZIP；测试超过 100MB 的文件，确认改为下载且页面未卡死。
5. 测试教程附件、两类证明材料、月度/全部时长 Excel。
6. 换用无权限账号访问同一接口，确认返回拒绝且分享层不公开文件地址。
7. 取消一次系统分享，再次点击确认可重试；断网后确认出现失败提示。
8. 将窗口扩大到 `sm` 断点以上，确认分享按钮消失，原下载和预览仍可用。

建议实测矩阵：Android Chrome、iOS Safari、微信内置浏览器、QQ 内置浏览器。微信或 QQ 内置浏览器若未实现文件型 Web Share，应验证其自动下载回退；能否直接出现微信/QQ目标由系统、浏览器版本和应用注册的分享能力共同决定。
